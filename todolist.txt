RULED: CHAPTERED MODE IS THE DELIVERY SHAPE (mentor, 2026-09-28)
=============================================================================
3-5 min per chapter x 5 chapters = 15-25 min, against a design built around a
4-minute video. An install session with a prerequisites card, a checkpoint per step
and a failure scene does NOT fit that budget -- not marginally, and not by tuning.
Five minutes is roughly four spoken commands plus a checkpoint and a pause; the uv
storyboard's FIRST chapter alone is four steps with three checkpoints.

  delivery unit      one video ~4 min   ->  a CHAPTER, 3-5 min
  total length       ~4 min              ->  15-25 min across 5 chapters
  scene budget       per video           ->  PER CHAPTER
  TARGET_MINUTES     per video           ->  per chapter (~4); the sum is the total
  source coverage    per video           ->  per chapter

A CHAPTER IS STANDALONE and must work alone: it states its start_state at the top,
and a learner arriving from a search result has not seen chapters 1-3. start_state
is the declaration that closes that gap, and _unclaimed_source_sections has no
opinion about it.

THREE CONSEQUENCES THAT ARE EASY TO MISS:
  1. Coverage is now per chapter, so the 12.3 ruling (every numbered concept claimed
     or the build refuses) applies PER CHAPTER. A 5-scene chapter cannot claim 7
     concepts, so the document's concept list is PARTITIONED across chapters and
     the partition is recorded in each chapter's start_state.
  2. AC#30's instruments become per chapter: loudness, caption geometry and the
     word-boundary check each run on that chapter's own artefact. A gate reading a
     concatenation is a control on the wrong side of a boundary, in exactly the way
     A18 was (see 12.2).
  3. The cheat-sheet card and the chapter marker are load-bearing, not polish. A
     learner joining at chapter 4 has no list of chapters 1-3's commands.

MIN_SCENES STAYS AT 5, deliberately. A 3-scene chapter is a prerequisites card, one
command and a checkpoint; the honest minimum for "a learner can tell whether it
worked" is five distinct beats. Lowering it to make a chapter fit would be tuning
the gate to the artefact -- the same error as widening a tolerance to absorb a mux.

HONEST LIMITATION: this changes the shape of the deliverable and the meaning of two
constants. It does NOT re-measure the gate against a 25-minute plan, because no
render exists at the new size. The first chapter render is the measurement, and if
the scene budget or the duration estimator is wrong at this scale, that render
will say so.

D2. LOUDNESS: GATE THE PUBLISHED FILE, not the pre-mux clip.
    Re-measured on output/mod03_gates_v013.mp4:
      published MP4      -16.7 LUFS,  -5.1 dBFS true peak
      pre-mux per clip   -16.1..-16.0 LUFS, -1.5 dBTP
      config target      -16.0 LUFS (LOUDNESS_TARGET), -1.5 dBTP (LOUDNESS_TP)
    A18 reads the pre-mux clip, so its reading point is on the wrong side of the
    mux boundary -- the same defect as AC#26, a control on the wrong side.
    Band: integrated -16.0 +/-1.0 LU, so the measured -16.7 passes and the band is
    not vacuous. True peak is a CEILING of <= -1.5 dBTP, not a band: being quieter
    than the ceiling is not a defect, so a two-sided band would invent one.
    Both targets are env-overridable, which is why the measured value is quoted
    and not the configured one.

D3. ENRICHMENT: COVERAGE, NOT INVENTION.
    If the source document is missing a step, enrichment does NOT write it. The
    baseline's own docstring says the lever is "coverage, not invention", and
    AC#19 already forbids fabrication on screen. A fabricated step would be on
    screen, spoken by the narration, and stamped with a source_refs pointer to
    something that does not say it.
    Mechanism is DETECTION: _unclaimed_source_sections, claim-based with NO
    token-overlap fallback -- overlap cannot tell "mentions the word" from
    "teaches the concept" (measured: concept 4 scores 0.70 overlap on the single
    word "tolerance", 0.75 after dropping common tokens).
    THE CHANGE: in the baseline it is a soft_finding that never refuses, so an
    untaught step can ship. Here it GATES. Every numbered concept must be claimed
    or the build refuses. Expect the first build to fail on this. That is the
    intent, not a regression.
    CONSEQUENCE FOR THE SOURCE DOC: it must carry a NUMBERED concept list. The
    detector prefers it and only falls back to inferred headings when it finds
    fewer than 3 numbered entries, so a concept dropped from the list becomes
    INVISIBLE rather than untaught. Ours carries 7.

D4. THE SOURCE DOCUMENT IS OURS TO WRITE. I recommended against it; the owner
    ruled otherwise and that is the decision. The provenance risk I named --
    "if I author the source, the source becomes me" -- is handled by the artefact
    rather than argued in prose: every claim in the file is tagged [MEASURED] or
    [CITED], and the file's own header says it is an agent-authored measured
    environment report, not vendor documentation. A video from it is grounded in
    that, and must not imply it is Astral's.

Same shape as the defect the source document shipped with, one layer up: a check
that cannot fail, or that fails wrongly, is worse than none because it is
believed.

  * A step whose command became `cat > /dev/null` while its prose still said
    "Creates src/main.py." PASSED every check. unshown-state cannot see it and
    cannot be asked to: the next step legitimately declares the file in its
    precondition. That is why undelivered-state is a SEPARATE check.
  * Prose satisfied a step's OWN state. A `state_change` promise may satisfy a
    LATER step; it may not satisfy the step that makes it.
  * A check that cried wolf 8 times on the real storyboard, all 8 false
    positives: inferring a tool's side effects from command text cannot tell that
    `uv init` created pyproject.toml, because the command never names it. Only a

  * A DEAD mkdir branch, found by a test: it tested token.startswith("-p ") but
    "mkdir -p src" splits into three tokens, so no token contains a space and the
    branch could never fire. It read as if mkdir was handled. It was not.

    later punctuation strip then leaves "a/" -- a path no file satisfies, so a step
    merely MENTIONING it in prose would be refused. Order is punctuation, then
    slash.
  * 3 false alarms on the first run, ALL 3 bugs in the check. Two were false
    NEGATIVES: a trailing full stop made "Creates src/main.py." yield
    "src/main.py.", so the step that CREATES the file looked like it did not.

    astral.sh/uv/install.sh, so every install step was reported as depending on a
    nonexistent file.
  * expected_output_pattern was scanned for paths that must pre-exist, but it is
    what a step PRINTS -- so every checkpoint was reported as an unshown
    dependency, when naming a path the learner should now see is precisely a
    checkpoint's job.
  * 3 lines removed as provably dead, and a duplicated docstring.
  * The unjustified-env check first treated an empty `env: {}` as "set" and fired
    on 5 innocent steps; and my insert landed inside an `if` body so it only ran
    for non-replayable steps, which a 0-gap result exposed.
  * A WEAK EXPECTED PATTERN, found by constructing the exact bad state: the old
