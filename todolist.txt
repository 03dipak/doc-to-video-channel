WHY V-1 DOES NOT NEED IT, measured rather than argued:
  cli.main's `render` branch spans lines 589-660 and calls NEITHER
  load_documents NOR plan_lesson -- it reads a saved plan.json. So the spike is a
  RENDER-PATH test, not a content test, and needs no document to plan from.
  What the gate does require is per-scene `topic` and a non-empty `source_refs`
  list (validate.py's _scene_metadata_problems), and that check is PRESENCE, NOT
  RESOLUTION: the refs are never opened and never have to exist.

WHY THAT IS EXACTLY WHY THE SPIKE MUST BE LABELLED:
  A presence-only check means a plan can point source_refs at nothing and still
  pass. That is fabricating provenance -- the one thing this project exists to
  prevent (the description is "code decides what is true"). So the V-1 fixture
  plan must carry an explicit fixture marker and its source_refs must SAY it is a
  fixture. A green render whose provenance points at an invented file is worse
  than no render, because it looks like evidence.

WHY I AM NOT WRITING IT:
  If I author the uv install document, the source becomes me. The video would
  then carry a provenance stamp pointing at my own invention, teaching possibly
  wrong install steps with the appearance of grounding -- "beautiful and wrong",
  which AGENTS.md names as the failure the viewer role is the only one to see and
  is explicitly NOT scoped to judge (truth belongs to the grounding gates). The
  document must be the owner's, or be a real upstream source that can be cited.

WHAT THE DOCUMENT MUST CONTAIN, for build to accept it:

  * Enough distinct material for at least MIN_SCENES=5 and at most 8 scenes, or

  * In a format A5 reads. .md is the low-risk choice; .docx only after A5 lands

ENRICHMENT RULED (mentor 2026-08-28) -- coverage, not invention.
  If the source document is missing a step, enrichment does NOT write it. The
  baseline's own docstring says the lever is "coverage, not invention", and
  AC#19 already forbids fabrication on screen. The mechanism is detection:
  _unclaimed_source_sections reports sections no scene claimed, judged by the
  assignment's own record -- claim-based, with NO token-overlap fallback, because
  overlap cannot tell "mentions the word" from "teaches the concept" (measured:
  concept 4 scores 0.70 overlap on the single word "tolerance", 0.75 after
  dropping common tokens).
  THE CHANGE: in the baseline it is a soft_finding that never refuses, so an
  untaught step can ship. Here it GATES. Every numbered concept must be claimed or
  the build refuses. Expect the first build to fail on this -- that is the point.
  CONSEQUENCE FOR THE SOURCE DOC: it must carry a numbered concept list. The
  detector prefers it and only falls back to inferred headings when it finds
  fewer than 3 numbered entries. A concept dropped from the list becomes
  INVISIBLE rather than untaught. sources/uv-getting-started.md carries 7.

THE STORYBOARD -- BUILT. storyboards/uv-install.storyboard.json
  5 chapters, 15 steps, 6-field step contract on every step. 14 replayable, 1 not
  (install-uv: it installs software and rewrites the shell profile, so re-running
  changes the machine under the test -- exempt WITH a stated reason).
  src/doc_to_video_channel/storyboard.py loads and checks it: contract
  completeness, elision, unshown-state, and undelivered-state. 35 tests, SEVEN of
  which are MUTATIONS proving the checks can fail.
  Ruled: the storyboard is the SINGLE source for two consumers -- the renderer and
  the replay/learner-only harness. A harness that parsed a transcript of the
  finished video would test the transcription, not the video.

  WHAT THE CHECKS GOT WRONG, because it is the same shape as the source document's
  own defect -- a validator that cannot fail, or that fails wrongly:
    * 3 false alarms on the first run, ALL 3 bugs in the check. Two were false
      NEGATIVES: a trailing full stop made "Creates src/main.py." yield
      "src/main.py.", so the step that CREATES the file looked like it did not.
    * a DEAD `mkdir` branch, found by a test: it tested token.startswith("-p ") but
      "mkdir -p src" splits into three tokens, so no token contains a space and the
      branch could never fire. It read as if mkdir was handled. It was not.
    * an rstrip ORDER bug: "a/.".rstrip("/") is a no-op, and the later punctuation
      strip then leaves "a/" -- a path no file satisfies, so a step merely MENTIONING
      it in prose would be refused.
    * a check that cried wolf 8 times on the real storyboard: inferring tool side
      effects from the command text cannot tell that `uv init` created
      pyproject.toml, because the command never names it. All 8 were false
      positives. Replaced with a DECLARED `creates_indirectly` field that a human
      can falsify by reading.
    * the check that prose alone satisfied a step's own state -- so a step whose
      command became `cat > /dev/null` while its prose still said "Creates
      src/main.py." passed. That is now undelivered-state, and it is separate
      precisely because the unshown-state check CANNOT see it: the next step
      legitimately declares the file in its precondition.
    * 3 lines removed as provably dead, and a duplicated docstring.
  Coverage is 100% of 173 statements and 48 branches, but that number was only
  reached after coverage was run and the misses were each explained or fixed. It
  was 93% when first measured.
